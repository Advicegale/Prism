# Symbol composition and import exploration

Click a named symbol in the live Topics diff. Its map follows source-visible assignments, object/dictionary wrapping, explicit constructions and resolved module bindings. It keeps the selected field/subobject context, excludes unrelated sibling exports and stops at receiver operations. Construction records an input/result dependency, not proof that a runtime value is returned unchanged. Ordinary exported functions merely using the tracked object remain usage endpoints, following the working product preference.

The investigation is global to the entity at the clicked revision. A factory's two results remain distinct even with a shared input. Selecting an alias resolves its canonical definition and preserves the clicked occurrence for inspection. Owned wrapper and class fields retain their own identity, even when two fields carry the same input. Origins walk only upstream; they do not add sibling consumers. File display merges paths without merging their semantic contexts or source anchors. A whole-package/module import can carry the selected context into a file that uses a sibling; that import does not make the sibling or its derived outputs part of the investigation.

## Reader behavior

Before uses `meta.merge_base`; After uses `meta.head`. Unified removals use Before, additions and context use After. Renamed paths are mapped for the selected side. Snippets read full retained committed source, including unchanged files and code outside diff hunks. Missing commits/checkouts are reported instead of falling back to current HEAD.

The popover is a floating window with 15px file titles/source and independently scrolling map/source regions. By default it takes the half of the viewport opposite the clicked token (viewports under 900px use the full frame), so the token and surrounding diff stay visible; the size button toggles to the full near-viewport frame (24px margins, capped at 1760×1100). Dragging the grip or the blank header (not the selectable title or path) or any resize edge/corner sets a custom frame, clamped to the viewport (minimum 440×380) and remembered in `localStorage` (`prism.exploration.layout`) until the size button resets it. A window narrower than 1100px stacks the tree above the source; wider windows show them alongside each other, divided by a draggable splitter (min 220px per pane; arrow keys nudge, double-click or Home resets) with a ratio remembered per orientation. When every file fits the map with padding, the whole graph is centered initially; otherwise the clicked occurrence’s file is centered. Its snippet opens first, even when its canonical definition is elsewhere. Definition changes the snippet; Clicked source restores the occurrence and recenters the tree. Maximize map and Maximize source (icons in the map footer and inspector header) hide the other pane; inspecting source from a maximized map returns to both panes.

One causal tree displays inputs to the left and consumers to the right. Expand upstream and Expand downstream advance independent scoped cursors without discarding the other branch; shared files and proven connections are merged. Combining these views never traverses from a shared input into unrelated sibling constructions. Changed files only defaults on, while the definition and clicked source remain visible even if unchanged. A proven carrier path connects a clicked alias through eligible changed files, retaining hidden intermediary evidence. Changed cards carry an amber edge and a Changed badge, unchanged cards a muted Unchanged label on a darker background, and the footer legend repeats both colors. Hovering a connection shows its evidence kinds and count (plus unchanged files an indirect edge passes through) as a tooltip; the selected connection stays highlighted and the inspector shows a `source → target · kinds` summary. Double-clicking the blank header toggles half and full size.

The frame stays fixed during inspection and expansion; a new diff click while open replaces the investigation without moving it, and a click after closing re-places the default frame opposite the new token. There is no outside-click dismissal, since the diff remains usable. A top-right X, Escape (ignored while typing in a field) and a Connections reopen control retain the investigation. Nodes, edges and individual anchors update snippets in place. A named snippet click replaces the investigation in the same box. Root changes cancel/ignore older responses, and failed lookups clear stale results. Expand upstream, Expand downstream, Changed files only, Clicked source and Definition share one toolbar above the panes. Each direction/filter retains its expanded projection. Map panning survives expansion, loading, resizing, splitter moves and reopening; only a new investigation recenters. The map pans by dragging its background (buttons and connection hit areas keep their own clicks) and zooms with the scroll wheel about the cursor, between 40% and 200%; floating zoom controls and the +/−/0 keys do the same, and Fit scales down (never above 100%) so every file is visible. Zoom resets to 100% for each new investigation and does not change source anchors or layout positions. The scroll area keeps empty padding (35% of the viewport on each side) around the scaled graph so the map can always be dragged, even when every file already fits. Loading progress is an overlay at the bottom-left of the window, so it never resizes the map. Main file selection, diff scroll, chats and reader layout are independent.

Test files are recognised from their path alone, so every indexed language is treated the same way: a `test`, `tests`, `__tests__`, `__mocks__`, `spec`, `specs`, `e2e`, `testdata`, `fixtures`, `itest` or `itests` directory; `.test.`, `.spec.` or `.e2e.` before the extension; a `test_`/`test-` prefix, `conftest.*` or `TestFoo`; and `_test`, `_tests`, `_spec`, `_unittest` or CamelCase `Test`, `Tests`, `Spec`, `IT` stems (`foo_test.go`, `FooTest.java`, `FooTests.cs`, `FooIT.java`). Test cards carry a **Test** badge and a dashed border and sit in a dashed **Tests** group beneath the other cards of their column (the clicked file never moves into it). **Hide tests** (toolbar, always present but disabled when the map has no tests, off by default, remembered with the window layout) removes test cards, their connections, stops inside them and any file reachable only through them; the footer counts the hidden tests. Detection is by path, so inline test modules (for example Rust `#[cfg(test)]`) and helpers outside test folders read as ordinary files. The same path check puts test files in a separate **Tests** group at the end of each topic's file list in Topics.

No names are premarked as links or drawn from a seed list. DOM caret/range text produces UTF-16 source columns through syntax spans, word marks, tabs and wrapping. The backend maps those columns onto exact UTF-8 source. Drag selection and modified clicks retain normal code behavior. Quoted static property/dictionary keys are fields; arbitrary values, comments, keywords, punctuation and JSX text are not investigation roots. Offline HTML remains static and has no live explorer.

## Coverage matrix

The behavioral tests select source positions in differently named passive fixtures, including definitions and references. Each required language passes field → construction → wrapper/assignment → cross-file import tests with negative sibling/operation-result exclusions. These are static syntax/binding adapters, not full compiler or runtime analysis.

| Construct | JS / TS / TSX | Python | Java |
| --- | --- | --- | --- |
| Module/local names, parameters, named functions, classes, methods | Supported, including lexical shadowing and typed/static class members | Supported for lexical functions/classes and ordinary parameters/assignments | Supported for classes/methods, parameters, fields and block locals |
| Nested static owned fields | Object properties and quoted keys | Global/nested dictionaries and quoted key accesses; explicit self fields | Class value fields, declared/inferred instance field contexts; types remain separate from values |
| Aliases/assignments and explicit wrapping | Supported; object shorthand and known-key object destructuring | Supported aliases and dictionary wrapping | Supported assignments/value fields and explicit constructor inputs |
| Input/result construction | Assigned bare factory calls and `new`; external named factories do not require callee inspection | Assigned bare calls and explicit inputs | Constructors and static factory inputs; instance receiver results stop |
| Cross-file bindings | Named/aliased/default/namespace imports; named/star/namespace re-exports, relative extensions/index files, tsconfig/jsconfig paths and explicit tracked package entries | Absolute/relative module globals, aliased from-imports and module namespaces | Package/class and static value imports, unambiguous same-package types |
| TSX | Expressions/components and imported expression names; JSX text is ignored | n/a | n/a |
| Progressive projection | Shared file merging, retained anchors, origins/consumers, hidden unchanged bridges, repeated-path/cycle stops | Same shared query model | Same shared query model |

Origins also explain unsupported/computed inputs and operation-result boundaries. A local alias of an unavailable external input retains its local definition and reports the missing origin.

Partial/unsupported forms stop explicitly: unknown/computed fields, object/dictionary spreads, positional/complex destructuring, callbacks and returned-object/indirect expression flows, dynamically mutated ownership, untyped instance dispatch, overload ambiguity, complex wildcard/package resolution and missing external implementations. Returned functions do not extend a general call graph. A valid declaration with no eligible connections still resolves and exposes its definition.

Language eligibility now follows **Graphify’s complete native dispatch registry**, not a Prism language allowlist. The installed 0.9.86 registry has **114 suffixes / 54 providers**, plus filename, shebang and source-aware routing (e.g. C/C++/Objective-C headers). Every dispatched provider contributes its native source-backed declarations, imports and references. New registered providers are admitted automatically; tests register previously unknown suffixes and a new custom extractor without adding Prism mappings. [Registry evidence](exploration-language-registry.json) records discovery rather than defining support.

Shared AST-shape enrichment discovers Graphify’s own grammars/configurations and handles lexical names, declaration/initializer fields, static members, dictionary/struct initializers, aliases, explicit construction inputs, wrappers and uniquely resolved module bindings. Additional precision rules remain for JS/TS/TSX, Python and Java. Native call/reference evidence stays a usage endpoint; it never implies that a return value preserves an input.

| Additional evidence | Proven behavior |
| --- | --- |
| Go, Rust, Ruby, C, Lua | Owned field → factory → wrapper → cross-file binding; origins, sibling exclusions and source anchors. Go package aliases, C includes, Rust qualified value imports, Ruby require-relative and Lua returned module values/objects are exercised. |
| C#, Kotlin, Swift, PHP | Static member/constructor/wrapper transfer and logging exclusions. Swift instance-field projection and PHP associative keys retain selected ownership. |
| 35 additional language/template formats | Position-based native/shared declaration roots with exact retained name spans: Go/Rust/Ruby/C/C++/C#/Kotlin/Scala/PHP/Swift/Lua/Zig/Bash/Elixir/Erlang/Julia/Fortran/Dart/OCaml/Common Lisp/Verilog/SQL/Pascal/Solidity/PowerShell/VB.NET/Groovy/COBOL/Terraform/Robot/DM/Objective-C++/Vue/Svelte/Astro. This declaration proof does not imply that every syntax form has a composition transfer. |
| Regex/custom extractors and embedded templates | Native proven roots/reference endpoints remain available when Graphify does not expose an initializer/member AST. Additional value transfers stop with a specific construct limit; the whole language is not rejected. |

Setup derives language parser requirements directly from Graphify package metadata, including its optional parser packages, without installing unrelated account/service extras. Missing parser/extraction dependencies identify the provider/path and produce incomplete analysis. Parser errors, invalid UTF-8, binary source and configured inventory omissions likewise identify their path/reason. These are static source facts, not full compiler/runtime analysis. A newly introduced AST shape can require a new shared normalization rule even though its native Graphify provider is already eligible.

Setup applies [pinned grammar corrections](../scripts/grammar-fixes/README.md) for JSX literal ampersands, C# pointer operands and PostgreSQL constructs found in the retained preview reports. Both native Graphify extraction and shared enrichment use the corrected grammars on the original source bytes. Pointer writes still stop with an explicit memory-alias boundary. Genuine parser failures retain “Parser could not fully analyze this syntax” coverage warnings; a clean syntax tree does not establish complete runtime or value-flow modeling. Parser versions and the adapter fingerprint invalidate older exploration caches automatically.

October 14 parser maintenance audited all eight retained preview reports at both head/merge-base revisions: **3,512 parsed files, zero parser failures**, down from 57 failing file instances across nine paths. All 16 exploration indexes were rebuilt with zero native provider errors. AHOY and PIN have no coverage omissions; WFArsenal retains ten oversized CSV/JSON omissions per revision under the existing source-size limit. The live SQL map and TSX/C# resolve/source APIs use the corrected caches. The original `Repeat & reminder` label and its byte/line coordinates remain intact. [Before/after evidence](exploration-parser-audit.json); 165 backend tests pass, including 39 new parser/source/negative cases.

Unknown static fields do not create speculative transfer edges. Ambiguous star barrels do not choose an arbitrary export. The distinct states are unresolved root, unresolved relationship, unsupported construct, usage endpoint, cycle, no further eligible connections, no further changed files, indexing, missing source and incomplete analysis.

## Index and API

`prism/exploration/graphify_adapter.py` is the private Graphify seam. Graphify **0.9.86** is pinned in pyproject.toml. The adapter reuses native dispatch/extraction/resolution, language configurations, grammars and import/export fact helpers. Native extraction reads a temporary tree containing only retained committed blobs and manifests; process-global Graphify resolver caches are protected by an extraction lock. Prism's existing committed-source and manifest-alias infrastructure supplies exact blobs/module paths. No installed package is patched and reviewed source is never executed.

The independent enriched model stores revision-pinned declarations, owned field paths, occurrences, source anchors, imports/identity/wrapping/construction relations and boundaries. Rendering groups facts by file; it does not infer eligibility. Field contexts are carried through identity transfers and wrapping. Construction enters a distinct result binding. Known constructor types support static instance-field/method reflection, including Python class calls and constructors reached through static wrappers. Instance-field projections preserve value ownership without treating a type reference as the value; multiple constructor types stop as ambiguous.

The cache lives alongside Graphify snapshots under each retained repository's `graphs/exploration-v2-<sha>-<fingerprint>.json`. The fingerprint includes the enrichment adapter version, complete provider registry, Graphify/all installed parser versions and repository limits. Installing a parser or adding a provider invalidates older indexes. Writes use unique temporary files followed by atomic replacement. Builds deduplicate per repository/revision/configuration on a separate two-worker pool; AI jobs cannot queue ahead of them. At most six completed revision indexes and 100 exploration cursors are retained in memory; index eviction expires its cursors. Old saved reports index lazily without rerunning providers or modifying narratives. Analysis and report loading never queue exploration indexes. The first symbol exploration request queues only its selected revision (Before or After); repeated requests share the same pending or cached build. The other revision stays unindexed until requested. A cold first exploration may therefore show an indexing state. The explicit prefetch helper is retained for opt-in tooling but is not called by the application. `graph.snapshot` and index builds share Graphify's extraction lock, since both use its process-global resolver caches.

| Endpoint | Contract |
| --- | --- |
| `POST .../resolve` | `{path, side: "old"|"new", line, column}`. Ignored syntax returns ignored; a genuine name returns indexing, resolved root/occurrence plus `projections.origins` and `projections.consumers`, or a specific limitation. Legacy `projection` remains the consumer view. Both cursors retain the clicked occurrence. The clicked file is classified while indexing is pending. |
| `POST .../expand` | `{side, root_id, direction: "consumers"|"origins", changed_only, query_id?, context_query_id?}`. Omitting `query_id` starts that root’s direction/filter view; passing it advances the server-owned frontier. Optional `context_query_id` preserves clicked-source focus when starting another view. Cursors validate report, root, revision and side; expansion additionally validates direction/filter. |
| `GET .../source` | `path`, `side`, `line`, optional `end_line`. Returns exact unmodified code/context, starting line, source anchors and SHA; bounded display ranges are identified. |

The server derives SHA from the report, never accepts arbitrary revisions or client graph data, and validates paths/source positions. Existing `PRISM_MAX_FILES=2500`, `PRISM_MAX_FILE_BYTES=600000` and `PRISM_MAX_TOTAL_BYTES=35000000` limits apply. Source requests show at most 100 lines and do not clip individual lines. Expansion budgets 12,000 semantic states per request; a resumable partial frontier is distinct from no more connections. Traversal walks through hidden unchanged files to the next eligible changed nodes and retains every displayed indirect edge's source anchors. A user-visible expansion step must grow the file map: after the initial query and after every expansion, `Query.settle()` applies any following layers that would only add occurrences or stops to files already displayed (a layer that adds a file or connection is rolled back and left for the click). Expand therefore never merely adds chips to existing cards; when nothing further can add a file or connection the direction reads complete. Repeated relationships close recursive wrappers; distinct incoming anchors remain inspectable.

Browser cancellation aborts the investigation requests and ignores stale responses. A shared revision build can continue for another investigation/cache reuse. Cancellation is not a completed empty search. Cached cursors expire after eviction/server restart; select the symbol again to reconstruct a view.

This [historical source evidence](exploration-real-source.json) records exact definitions/importers and four PostgreSQL parser omissions; the [current parser audit](exploration-parser-audit.json) supersedes those diagnostic counts. These names were independent of the earlier prototype’s fixed recipientUserId seed.

The sweep excludes unavailable external imports and synthetic default bindings spanning an expression rather than a source name. This does not measure every dynamic reference or relationship. Broader native extraction adds cost compared with the original five-language index; the cache prevents repeating it on each symbol click.

A synthetic 501-file wrapper chain indexed in **575.83 ms** and traversed in **40.02 ms**, showing only its first/last changed files while retaining 499 hidden files. These observations do not establish a universal latency target. Field/context growth, source size, parser errors and many merged routes affect cost.
