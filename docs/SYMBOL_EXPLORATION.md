# Symbol composition and import exploration

Click a named symbol in the live Topics diff. Its map follows source-visible assignments, object/dictionary wrapping, explicit constructions and resolved module bindings. It keeps the selected field/subobject context, excludes unrelated sibling exports and stops at receiver operations. Construction records an input/result dependency, not proof that a runtime value is returned unchanged. Ordinary exported functions merely using the tracked object remain usage endpoints, following the working product preference.

The investigation is global to the entity at the clicked revision. A factory's two results remain distinct even with a shared input. Selecting an alias resolves its canonical definition and preserves the clicked occurrence for inspection. Owned wrapper and class fields retain their own identity, even when two fields carry the same input. Origins walk only upstream; they do not add sibling consumers. File display merges paths without merging their semantic contexts or source anchors. A whole-package/module import can carry the selected context into a file that uses a sibling; that import does not make the sibling or its derived outputs part of the investigation.

## Reader behavior

Before uses `meta.merge_base`; After uses `meta.head`. Unified removals use Before, additions and context use After. Renamed paths are mapped for the selected side. Snippets read full retained committed source, including unchanged files and code outside diff hunks. Missing commits/checkouts are reported instead of falling back to current HEAD.

The popover has fixed initial bounds, independently scrolling map/source regions, a top-right X, Escape/outside dismissal and a Connections reopen control. Nodes, edges and individual anchors update snippets in place. A named snippet click replaces the investigation in the same box. Root changes cancel/ignore older responses. Direction/filter views retain their own expanded projections. Main file selection, diff scroll, chats and reader layout are independent.

No names are premarked as links or drawn from a seed list. DOM caret/range text produces UTF-16 source columns through syntax spans, word marks, tabs and wrapping. The backend maps those columns onto exact UTF-8 source. Drag selection and modified clicks retain normal code behavior. Quoted static property/dictionary keys are fields; arbitrary values, comments, keywords, punctuation and JSX text are not investigation roots. Offline HTML remains static and has no live explorer.

## Coverage matrix

The behavioral tests select source positions in differently named passive fixtures, including definitions and references. Each required language passes field → construction → wrapper/assignment → cross-file import tests with negative sibling/operation-result exclusions. These are static syntax/binding adapters, not full compiler or runtime analysis.

Origins also explain unsupported/computed inputs and operation-result boundaries. A local alias of an unavailable external input retains its local definition and reports the missing origin.

Partial/unsupported forms stop explicitly: unknown/computed fields, object/dictionary spreads, positional/complex destructuring, callbacks and returned-object/indirect expression flows, dynamically mutated ownership, untyped instance dispatch, overload ambiguity, complex wildcard/package resolution and missing external implementations. Returned functions do not extend a general call graph. A valid declaration with no eligible connections still resolves and exposes its definition.

Language eligibility now follows **Graphify’s complete native dispatch registry**, not a Prism language allowlist. The installed 0.9.86 registry has **114 suffixes / 54 providers**, plus filename, shebang and source-aware routing (e.g. C/C++/Objective-C headers). Every dispatched provider contributes its native source-backed declarations, imports and references. New registered providers are admitted automatically; tests register previously unknown suffixes and a new custom extractor without adding Prism mappings. [Registry evidence](exploration-language-registry.json) records discovery rather than defining support.

Shared AST-shape enrichment discovers Graphify’s own grammars/configurations and handles lexical names, declaration/initializer fields, static members, dictionary/struct initializers, aliases, explicit construction inputs, wrappers and uniquely resolved module bindings. Additional precision rules remain for JS/TS/TSX, Python and Java. Native call/reference evidence stays a usage endpoint; it never implies that a return value preserves an input.

Setup derives language parser requirements directly from Graphify package metadata, including its optional parser packages, without installing unrelated account/service extras. Missing parser/extraction dependencies identify the provider/path and produce incomplete analysis. Parser errors, invalid UTF-8, binary source and configured inventory omissions likewise identify their path/reason. These are static source facts, not full compiler/runtime analysis. A newly introduced AST shape can require a new shared normalization rule even though its native Graphify provider is already eligible.

Unknown static fields do not create speculative transfer edges. Ambiguous star barrels do not choose an arbitrary export. The distinct states are unresolved root, unresolved relationship, unsupported construct, usage endpoint, cycle, no further eligible connections, no further changed files, indexing, missing source and incomplete analysis.

## Index and API

`prism/exploration/graphify_adapter.py` is the private Graphify seam. Graphify **0.9.86** is pinned in pyproject.toml. The adapter reuses native dispatch/extraction/resolution, language configurations, grammars and import/export fact helpers. Native extraction reads a temporary tree containing only retained committed blobs and manifests; process-global Graphify resolver caches are protected by an extraction lock. Prism's existing committed-source and manifest-alias infrastructure supplies exact blobs/module paths. No installed package is patched and reviewed source is never executed.

The independent enriched model stores revision-pinned declarations, owned field paths, occurrences, source anchors, imports/identity/wrapping/construction relations and boundaries. Rendering groups facts by file; it does not infer eligibility. Field contexts are carried through identity transfers and wrapping. Construction enters a distinct result binding. Known constructor types support static instance-field/method reflection, including Python class calls and constructors reached through static wrappers. Instance-field projections preserve value ownership without treating a type reference as the value; multiple constructor types stop as ambiguous.

The cache lives alongside Graphify snapshots under each retained repository's `graphs/exploration-v2-<sha>-<fingerprint>.json`. The fingerprint includes the enrichment adapter version, complete provider registry, Graphify/all installed parser versions and repository limits. Installing a parser or adding a provider invalidates older indexes. Writes use unique temporary files followed by atomic replacement. Builds deduplicate per repository/revision/configuration on a separate two-worker pool; AI jobs cannot queue ahead of them. At most six completed revision indexes and 100 exploration cursors are retained in memory; index eviction expires its cursors. Old saved reports index lazily without rerunning providers or modifying narratives.

| Endpoint | Contract |
| --- | --- |
| `POST .../resolve` | `{path, side: "old"|"new", line, column}`. Ignored syntax returns ignored; a genuine name returns indexing, resolved root/occurrence/projection, or a specific limitation. The clicked file is classified while indexing is pending. |
| `POST .../expand` | `{side, root_id, direction: "consumers"|"origins", changed_only, query_id?}`. Omitting a cursor starts that root's direction/filter view; passing it advances the server-owned frontier. Cursors are validated against report, root, revision, side and filter. |
| `GET .../source` | `path`, `side`, `line`, optional `end_line`. Returns exact unmodified code/context, starting line, source anchors and SHA; bounded display ranges are identified. |

The server derives SHA from the report, never accepts arbitrary revisions or client graph data, and validates paths/source positions. Existing `PRISM_MAX_FILES=2500`, `PRISM_MAX_FILE_BYTES=600000` and `PRISM_MAX_TOTAL_BYTES=35000000` limits apply. Source requests show at most 100 lines and do not clip individual lines. Expansion budgets 12,000 semantic states per request; a resumable partial frontier is distinct from no more connections. Traversal walks through hidden unchanged files to the next eligible changed nodes and retains every displayed indirect edge's source anchors. Repeated relationships close recursive wrappers; distinct incoming anchors remain inspectable.

Browser cancellation aborts the investigation requests and ignores stale responses. A shared revision build can continue for another investigation/cache reuse. Cancellation is not a completed empty search. Cached cursors expire after eviction/server restart; select the symbol again to reconstruct a view.

## Measured evidence

On this Linux workspace, the retained AHOY25 head `252cc55ceded3c335927e1b76bcd8741caa0b815` contains 146 retained text files. Native Graphify dispatched 131 files and syntax enrichment parsed 124; the shared model has 5,687 entities and 22,787 relations. A cold final-registry build took **4,184.38 ms**; disk-cache restoration took **361.68 ms**. In-memory resolution plus complete changed-file traversal for `applyWorkspaceMutation` and `enqueueNotificationEvent` took **0.62 / 0.43 ms**, excluding HTTP/Git revision verification. [Source evidence](exploration-real-source.json) records exact definitions/importers and four PostgreSQL migration parser-error omissions. These names were independent of the earlier prototype’s fixed recipientUserId seed.

A position-based sweep resolved all 4,530 extracted ordinary named declarations (variables, parameters, functions, types, fields and methods). The sweep excludes unavailable external imports and synthetic default bindings spanning an expression rather than a source name. This does not measure every dynamic reference or relationship. Broader native extraction adds cost compared with the original five-language index; the cache prevents repeating it on each symbol click.

A synthetic 501-file wrapper chain indexed in **575.83 ms** and traversed in **40.02 ms**, showing only its first/last changed files while retaining 499 hidden files. These observations do not establish a universal latency target. Field/context growth, source size, parser errors and many merged routes affect cost.

Desktop native-preview QA exercised a real isolated two-commit repository through the production APIs/React reader: unmarked field click, default changed-only view, hidden client/policy bridges, two incoming connections into one screen.ts, individual anchors, unchanged source inspection, new symbol selection inside snippets, unchanged 880×680 popover bounds/main file/diff scroll, Before/After renamed fields, X/Escape/reopen/focus, directions/filtering and ordinary literal/text-selection behavior. The evergreen correction additionally checked an actual Go nested field diff, package aliases and hidden client/policy paths, unchanged main file/scroll/bounds during screen.go snippet inspection, deduplicated highlights, and an ordinary Dart helper root through its native custom extractor. Whole-package imports preserve selected context; logger outputs stay excluded even where the package import itself is relevant.
